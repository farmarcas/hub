# Data Model — Hub de Inovação Farmarcas (MVP)

Model conventions:
- **Identifiers and names:**
  - PK is UUIDv7 generated by the app (`@default(uuid(7)) @db.Uuid`).
  - Tables are plural, `snake_case`.
  - Instants use `timestamptz(3)`.
- **Text:** human-facing text uses the ICU `pt_br` collation (created by hand in the migration).
- **Implementation:** source of truth in `backend/node/prisma/schema.prisma`; partial indexes, collation and CHECKs are added by hand to the migration (`--create-only`).

## Entities

### users (already exists, gains `is_admin`)
| Column | Type | Rule |
|---|---|---|
| id | uuid PK | |
| name | text COLLATE pt_br | required |
| email | text | required; unique among active rows (`users_email_active_uidx`, already exists) |
| is_admin | boolean | default `false` |
| deleted_at, created_at, updated_at | timestamptz | soft delete |

- **Origin:** Radar. In the MVP it comes from the seed, and the Hub has no endpoint to create or edit users.
- **PII:** name and e-mail. These are the minimum needed to identify and pick people. Retention follows the Radar.

### solutions
| Column | Type | Rule |
|---|---|---|
| id | uuid PK | |
| name | text COLLATE pt_br | required, max. 120 |
| url | text | required; `CHECK (url ~ '^https://')` |
| objective | text | required |
| description | text | required, short (max. 160, one line) |
| category_id | uuid FK → categories | required |
| status | enum `solution_status` (`in_review`, `published`) | default `in_review` |
| access_all | boolean | default `false` |
| archived_at | timestamptz | null = active |
| created_at, updated_at | timestamptz | |

Index: `solutions_visible_idx (status) WHERE archived_at IS NULL`.

### solution_groups (relation in the map, required ≥ 1)
- Columns: `solution_id` FK, `group_id` FK.
- PK on the pair, plus index `solution_groups_group_id_idx`.

### solution_related (symmetric relation between solutions, optional)
- Columns: `solution_a_id` FK, `solution_b_id` FK.
- PK on the pair, `CHECK (solution_a_id < solution_b_id)`, plus index on `solution_b_id`.

### solution_access_groups
- Columns: `solution_id` FK, `group_id` FK.
- PK on the pair, plus index on `group_id`.

### solution_access_users
- Columns: `solution_id` FK, `user_id` FK.
- PK on the pair, plus index on `user_id`.

Link-table FKs use `ON DELETE CASCADE` only toward the technical link row. Domain parents never undergo a physical `DELETE` (see research R6).

## Validation rules (service + database)

| Rule | Where |
|---|---|
| ≥ 1 group in `solution_groups` to save (FR-004) | service (`SOLUTION_REQUIRES_GROUP`, 400) |
| `access_all` OR ≥ 1 access group OR ≥ 1 access user (FR-005) | service (`SOLUTION_REQUIRES_ACCESS`, 400) |
| URL `https://` (FR-002) | Zod + DB CHECK |
| Groups/users/solutions referenced exist and are active | service (`REFERENCE_NOT_FOUND`, 400 with `details`) |
| Solution does not relate to itself | service |
| Group name unique among active rows (FR-009) | service (`GROUP_NAME_TAKEN`, 409) + partial index |
| Duplicate category returns the existing one | service + unique index |

## State transitions

- **Solution:**
  - `in_review` ⇄ `published` by editing.
  - Archive: `archived_at = now()`.
  - Restore: `archived_at = null`.
  - Visible in the globe ⇔ `published` and `archived_at IS NULL` and `canView`.
- **Group:**
  - Active → deleted (`deleted_at`).
  - The deletion removes its rows in `group_members`, `solution_groups` and `solution_access_groups`, in a single transaction.

## Derived rule: `canView(solution, viewer)`

```
solution.status = published
AND solution.archived_at IS NULL
AND ( solution.access_all
      OR viewer.id ∈ solution_access_users
      OR viewer.groups ∩ solution_access_groups ≠ ∅ )
```

Admins follow the same rule in the globe. In the admin screens they see everything.

## Group deletion impact (FR-011)

For group G:
- `affectedSolutions` = solutions with G in `solution_groups` or in `solution_access_groups`.
- `affectedPeople` = members of G.
- `orphanedByGroup` = solutions whose only group is G.
- `orphanedByAccess` = solutions with `access_all = false`, no access users, and G as their only access group.
